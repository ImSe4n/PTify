# Piano Transcriber — dependencies
#
# Install into a VENV, not globally:
#     python -m venv .venv
#     .venv\Scripts\activate
#     pip install -r requirements.txt
#
# Why a venv matters here: this machine's global environment has
# torch 2.4.0 + numpy 2.2.6, which is a broken combination (torch 2.4 was
# compiled against numpy 1.x and cannot convert tensors to arrays under
# numpy 2.x). The pins below are a known-good set. Run
# `python -m transcriber --doctor` to verify.
#
# NOTE ON TORCH: no usable CUDA GPU was found on this machine (AMD
# integrated graphics, 1GB shared VRAM), so
# these pins use the CPU wheel (much smaller). Offline transcription does not
# need a GPU — a 3-minute file takes ~3.3 minutes on CPU. If you later add an
# NVIDIA GPU, install the CUDA build FIRST for faster batch processing:
#
#   pip install torch --index-url https://download.pytorch.org/whl/cu121
#
# BASIC-PITCH DOES NOT RESOLVE ON PYTHON 3.12, AND THIS FILE THEREFORE DOES
# NOT INSTALL IN ONE COMMAND. Verified on a from-scratch 3.12.5 venv:
#
#   basic-pitch 0.4.0 requires resampy<0.4.3, and this file pins ==0.4.3
#   basic-pitch 0.4.0 requires tensorflow<2.15.1, which has no 3.12 wheel
#
# The second has no workaround at these pins: the wheel does not exist. An
# environment built up incrementally hides both, which is why this went
# unnoticed for so long -- the conflict only surfaces when pip resolves the
# whole file at once, and `pip install -r requirements.txt` does exactly that.
#
# INSTALL IN TWO STEPS. Everything except the optional basicpitch engine:
#
#   findstr /v "basic-pitch onnxruntime" requirements.txt > req-core.txt
#   pip install -r req-core.txt
#
# then, ONLY on Python <= 3.11 and ONLY if you want that engine (its resolver
# also tries to build numpy from source, hence --no-deps):
#
#   pip install --no-deps basic-pitch onnxruntime pretty_midi mir_eval \
#       resampy importlib_resources
#
# MEASURED without basic-pitch: 1,279 tests pass, 13 skip. The skips are
# `test_remote_host_weights.py`, which needs `modal` -- NOT basicpitch. The
# bytedance, ptify and remote engines are all unaffected.

# --- Core ---
numpy==1.26.4               # MUST be <2.0 for the torch 2.2 / librosa ABI
librosa==0.10.2.post1       # audio decode + resampling
soundfile==0.14.0           # WAV/FLAC I/O behind librosa
ffmpeg-python==0.2.0        # mp3/m4a decode support
resampy==0.4.3              # resampling backend

# --- Transcription engines ---
torch==2.2.2                # CPU wheel; see CUDA note above
piano_transcription_inference==0.0.5   # ByteDance piano AMT — DEFAULT engine
basic-pitch==0.4.0          # Spotify multi-instrument AMT — fast alternative
onnxruntime==1.28.0         # ONNX runtime backing basic-pitch on Windows

# --- MIDI ---
pretty_midi==0.2.11.post0   # MIDI construction and inspection
mido==1.3.2                 # low-level MIDI file I/O

# --- Evaluation (Phase 12) ---
mir_eval==0.8.2             # standard transcription metrics (note onset F1)

# --- Real-audio corpus (Phase 13) — NO NEW DEPENDENCIES ---
# evaluation/corpus.py fetches MAESTRO test-split tracks individually from the
# ddPn08/maestro-v3.0.0 HuggingFace mirror. Those URLs serve single files over
# plain HTTPS with no auth, so it uses urllib from the stdlib.
#
# huggingface_hub was considered and rejected: it would add three packages
# (huggingface_hub, pyyaml, tqdm) to a venv whose torch 2.2 / numpy <2 ABI
# pinning is documented above as fragile, in exchange for nothing this needs.
# If a future phase wants resumable or parallel dataset downloads, that is the
# point to reconsider it.

# --- Tests ---
pytest==8.3.4

# --- Sheet music (Phase 3) ---
# Beat tracking uses librosa.beat (already required above). madmom is the
# better-known choice but caps at Python <3.10 and cannot be installed here.
#
# Verified not to disturb the numpy<2 pin above: installing these leaves
# numpy at 1.26.4, so the torch 2.2 ABI is intact.
music21==10.5.0             # MusicXML export, key/meter inference
verovio==6.2.1              # MusicXML -> SVG engraving (no MuseScore needed)
# Verovio has NO PDF output (`renderToPDF` does not exist), so PDF goes
# SVG -> svglib -> reportlab. test_verovio_has_no_pdf_renderer guards this.
svglib==2.1.0
reportlab==5.0.0

# --- Backend (Phase 4) ---
# Verified not to disturb the numpy<2 pin above: none of these depend on numpy
# at all, and installing them left numpy at 1.26.4 / torch at 2.2.2+cpu with
# `--doctor` still reporting the ABI OK. Pydantic v2 arrives with FastAPI and is
# the project's first use of it — nothing before Phase 4 needed a schema layer.
#
# INSTALL THE PROJECT ITSELF TOO. pyproject.toml explains why in full, but in
# short: notation/ imports from transcriber/, which until Phase 4 worked only
# because the repo root happened to be on sys.path. A uvicorn worker does not
# start in the repo root.
#
#     pip install -e . --no-deps
#
# --no-deps matters — it keeps a resolver away from the pins above.
fastapi==0.115.6
uvicorn[standard]==0.34.0   # ASGI server; [standard] adds the reload watcher
python-multipart==0.0.20    # multipart/form-data — FastAPI needs it for uploads
sse-starlette==2.2.1        # SSE with built-in heartbeats. The heartbeat is not
                            # cosmetic: ByteDance reports NO progress during its
                            # multi-minute inference (bytedance.py:97), so the
                            # stream would otherwise go silent and look hung.
httpx==0.28.1               # required by fastapi.testclient; tests only

# arq + redis are NOT installed. The job queue ships with an in-process backend
# that needs no infrastructure, and `api/arq_queue.py` sits behind the same
# JobQueue interface for when there is somewhere to deploy it (Phase 10). Redis
# does not run natively on Windows, so making it mandatory now would mean no
# backend at all on this machine.
#   arq==0.26.3
